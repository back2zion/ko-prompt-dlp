# AX필터 브라우저 확장 (Chrome, Manifest V3)

ChatGPT·Claude·Gemini 입력창에서 **전송 직전** 프롬프트를 가로채 AX필터 검사 API로 보내고,
결과에 따라 허용·마스킹·차단합니다. 서버(`../server`)의 클라이언트 측입니다.

## 구성
| 파일 | 역할 |
|---|---|
| `manifest.json` | MV3 선언 (대상 사이트, 권한, 콘텐츠/백그라운드 스크립트) |
| `filter-core.js` | 사이트 선택자 매핑과 응답 해석 (DOM·확장 API 비의존, 단위 테스트 대상) |
| `content.js` | Enter/전송 버튼 가로채기, 검사 호출, 배너 표시 |
| `background.js` | 검사 API 호출 (서버 연결 실패 시 기본 '전송 보류'로 안전 동작) |
| `options.html/js` | 서버 주소·에이전트 키·실패 모드 설정 (chrome.storage) |

## 동작
- **허용**: 그대로 전송
- **마스킹**: 입력창의 민감정보를 `[라벨]`로 치환하고 배너 표시 — 사용자가 **확인 후 다시 전송**
- **차단**: 전송을 막고 안내 배너 표시
- **서버 연결 실패**: 기본값은 전송 보류(안전). 옵션에서 '그대로 전송'으로 변경 가능

## 설치 (개발자 모드)
1. `chrome://extensions` → 개발자 모드 켜기 → "압축해제된 확장 프로그램 로드" → 이 폴더 선택
2. 확장 옵션에서 서버 주소와 에이전트 API 키 입력

## 테스트
```
cd test
node unit.mjs                 # filter-core.js + background.js 단위 테스트
node e2e.mjs                  # 모의 채팅 페이지 + 로컬 API로 가로채기 전 과정 검증 (playwright, python3 필요)
```
`e2e.mjs`는 로컬에서 `../server`를 띄우고 모의 채팅 페이지에 `content.js`를 주입해
허용/마스킹/차단과 전송 버튼 경로를 실제 브라우저로 확인합니다.

## 한계
- 대상 사이트는 UI가 자주 바뀌는 React 앱이라 `filter-core.js`의 선택자는 best-effort이며 주기적 갱신이 필요합니다.
- 실제 ChatGPT/Claude/Gemini 화면에서의 동작은 각 사이트에 로그인해 직접 확인해야 합니다(이 저장소 테스트는 모의 페이지 기준).
- 확장은 사용자가 끄거나 제거할 수 있으므로, 조직 차원 강제에는 서버측 프록시와 MDM 정책 배포가 함께 필요합니다.
